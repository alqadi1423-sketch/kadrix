# وكلاء الذكاء الاصطناعي وMCP

في Kadrix خادم مدمج لبروتوكول [Model Context Protocol](https://modelcontextprotocol.io)، فتستطيع أدوات البرمجة بالذكاء الاصطناعي مثل Claude Code وCursor وVS Code البحث عن المهام وتعديلها والتعليق وتسجيل الوقت، ضمن الصلاحيات التي تعطيها لها.

## إضافة وكيل

1. يفتح المشرف **الإعدادات ← الوكلاء** ويضيف وكيلًا، مثل "Claude Code". اترك خيار "يستطيع إنشاء المهام وتعديلها" مفعلًا ما لم تُرده للقراءة فقط.
2. انسخ الرمز الظاهر، فهو يظهر مرة واحدة.
3. اربط أداتك بأحد الأوامر الظاهرة هناك.

Claude Code:

</div>

```bash
claude mcp add --transport http kadrix https://kadrix.example.com/api/mcp \
  --header "Authorization: Bearer kdx_..."
```

<div dir="rtl">

العملاء الآخرون (JSON):

</div>

```json
{ "mcpServers": { "kadrix": { "type": "http", "url": "https://kadrix.example.com/api/mcp",
  "headers": { "Authorization": "Bearer kdx_..." } } } }
```

## ما يستطيعه الوكلاء

| الأداة | العمل |
|---|---|
| `list_projects` و`list_states` و`list_members` | عرض المشاريع وحالات سير العمل والأشخاص |
| `search_issues` | البحث في المهام بالنص (عربي أو إنجليزي) أو المشروع أو الحالة أو المسؤول |
| `get_issue` | المهمة بوصفها ومهامها الفرعية وارتباطاتها وتعليقاتها |
| `create_issue` و`update_issue` | إنشاء المهام وتعديلها (لصلاحية الكتابة فقط) |
| `add_comment` و`log_time` | التعليق وتسجيل الوقت (لصلاحية الكتابة فقط) |
| `search_docs` | البحث في مستندات المساحة |

كل أداة تمر بنفس الواجهة البرمجية وفحوص الصلاحيات التي يمر بها شخص يحمل الرمز نفسه، وكل ما يفعله الوكيل يظهر في السجل باسمه. ووكيل القراءة فقط لا يرى أدوات الكتابة أصلًا.

## الرموز الشخصية

يستطيع كل شخص إنشاء رموزه من **الإعدادات ← رموز الوصول البرمجي** واستخدامها مع خادم MCP أو [الواجهة البرمجية](api.md)، وتعمل باسمه.

## إزالة وكيل

زر **إزالة** يلغي رمزه وعضويته فورًا، ويبقى عمله السابق في السجل باسمه.
